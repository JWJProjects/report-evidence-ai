# 驗證／驗收矩陣｜案跡

「已測」為本機合成案例的驗證結果。導入時以核定需求、實際權限、正式環境與獨立資料驗證第二節的項目。

## 1. 展示功能與證據

| 測試 ID／需求 | 操作 | 預期結果 | 已取得證據 |
| --- | --- | --- | --- |
| T-01／FR-01 | 由教育案件切到施政案件；輸入無效數字；切回原案件 | 欄位與文件集不同；不合格式不得提交；原案件狀態不受切換改變 | 單元測試；實機確認模板切換、來源不同及原狀態不變 |
| T-02／FR-02 | 送審後先空白退回，再填補正原因；修改場次並重整，然後重送與核准 | 無理由不得退回；退回才可修改；已存內容重整後仍在；稽核事件依序呈現 | 單元與實機；[退回畫面](../assets/04-returned.png) |
| T-03／FR-03 | 核准前嘗試發布；核准後發布並匯出 JSON | 核准前不得發布；預覽不含審查意見／補充佐證；內部 JSON 有狀態、修改後場次與六筆事件 | 單元與實機；[發布後畫面](../assets/01-workflow.png)／擷取實際下載內容 |
| T-04／FR-04 | 依問題檢視摘錄、版本及原文段落；另新增一份合成問卷文字再查 | 可定位對應段落；更新索引後能找到新原文，而非固定回應 | 實機原文定位與重索引；[檢索評估](../assets/05-evaluation.png) |
| T-05／FR-05 | 查「成果報告交付期限？」及「個資保存年限多久？」 | 並列三個不同日期，不選最終值；後一題無證據時不顯示答案 | 單元與實機；[日期衝突](../assets/02-conflict.png)、[證據不足](../assets/03-mobile-gap.png) |
| T-06／IF-01 | 匯入[合流實際匯出的合成摘要](../examples/qa-evidence.json)，再查「資料品質檢查」；另測無效合計、模板或額外欄位 | 摘要可回查 18／13／1／4；無效格式拒絕，不收原始列 | 成功路徑實機、拒絕路徑單元；[跨案介接畫面](../assets/06-integrated.png) |
| T-07／NFR-01 | 以 390 px 寬度檢視證據不足畫面 | 主要區塊可閱讀且無橫向溢位 | 實機；[手機寬度畫面](../assets/03-mobile-gap.png)，非完整無障礙稽核 |

**重跑方式：**`npm test` 執行 8 項單元測試；`npm run evaluate` 以合成 12 題執行逐題評估；另附 [Qt WebEngine 步驟與擷取腳本](../tests/qt_webengine_capture.py)、[可選 Playwright 煙霧測試](../tests/browser_smoke.py)。[實機紀錄](../assets/qt-smoke-status.json)為 22 個腳本步驟。原文指標的 9 題只涵蓋有標註原文的問題；不把「證據不足」算作命中。

## 2. 正式導入驗收前必補

| 驗收閘門 | 可檢驗的應交證據 | 展示狀態 |
| --- | --- | --- |
| 權限與稽核 | 機關核定角色矩陣、真實登入、跨角色／跨單位隔離、稽核完整性測試 | 未實作正式權限或稽核庫 |
| 資料與介接 | 核定欄位字典、資料分類、正式介面契約、身分驗證與錯誤處理測試 | 僅實測本機合成彙總，無正式 API |
| 公開、資安與維運 | 使用核定公開欄位做實際發布、撤回與還原演練；掃描與缺失處理、備份復原、操作訓練紀錄 | 未實作，不視為通過 |
| 檢索品質與實務準則 | 機關提供獨立測試集與權責規則，報告誤找、漏找、證據不足、衝突與人工覆核效果 | 只有合成資料自測，不可外推 |

正式門檻、缺失等級及簽核人由機關在測試前核定。驗收結果應紀錄版本、前置資料、執行人、實際結果、證據、例外及複驗情況。
