# 需求規格｜案跡機關成果填報與佐證審核

以成果填報、補正、原文查核及公開版檢視為需求基線。導入前確認作業權責、欄位、時程、資安基準及驗收條件。

## 1. 作業目標與角色

| 角色 | 作業責任 | 產出 |
| --- | --- | --- |
| 填報人 | 選模板、填寫必填欄位、補附佐證、送審；留意退回原因 | 草稿、送審／補正版本、佐證 |
| 審核人 | 對照原文、確認內容與公開範圍、寫明補正原因或核准 | 審查決定與理由、簽核軌跡 |
| 發布人 | 確認核准狀態及對外欄位、執行發布 | 公開版預覽；正式環境另需發布權限與目的端 |
| 資訊與業務窗口（正式導入） | 資訊窗口訂介接與資安規格；業務窗口核定欄位及流程與評估樣本 | 介接清單、角色矩陣、欄位字典、驗收基準 |

**主路徑：**草稿 → 審查中 → 已核准 → 已發布。  
**補正路徑：**審查中 → 已退回（原因必填）→ 補正後再送審。  
展示模式不驗證實際身分；示意角色不構成權限控管或核准憑證。

## 2. 需求基線

| ID | 展示版功能基線 | 正式導入須確認或實作 |
| --- | --- | --- |
| FR-01 模板 | 兩套模板獨立維護草稿、來源、必填與公開欄位。數字欄位驗證非負整數。 | 各處室欄位字典、機關代碼、期別規則、多份案件生命週期、模板版本／異動通知 |
| FR-02 流程 | 審查期不可編輯；退回理由必填；每次狀態轉換含角色、時間、理由及前後狀態。 | SSO、最小權限、審核與發布職責分離、會辦／代理、不可任意改寫的伺服器端稽核 |
| FR-03 交付與公開 | 僅核准後可發布示範；預覽依模板公開白名單顯示，不帶審查意見或原始佐證。內部 JSON 另含狀態、欄位、事件、使用者補附佐證，不作對外資料。 | 實際發布介面與權限、資料分級、公開前覆核、遮蔽策略、撤回更正、封存與保留政策 |
| FR-04 可查核證據 | 從模板文件與補附文字建索引；中文單字／雙字詞 BM25 排序，顯示版本、日期、段落及摘錄。 | 文件進件、權限與版本治理；PDF/OCR、可依角色限制檢索；實場證據測試與持續抽測 |
| FR-05 失敗分流 | 同一交付期限檢出多個日期則並列原文；證據不足或複合問句不給結論。 | 機關須訂文件有效性、人工確認責任及錯誤回報路徑；依實場資料調整門檻及測量漏找／誤找 |
| IF-01 彙總介接 | 只收合成標記與允許的計數；檢查合計、模板、欄位及檔案上限後，轉為固定措詞的佐證段落。不讀原始列。 | 雙方確認資料交換約定、介接權限、來源簽章／完整性、例外及留存 |
| NFR-01 操作與資料環境 | 以瀏覽器本機執行、無外部 API；支援 390px 寬度的例示畫面。重新整理可回復已儲存狀態。 | 資安掃描、無障礙檢測、效能／可用性、資料庫、備份還原、監控、正式訓練與維運 |

## 3. 配置、介接及交付

- **配置點：**[`workflow.js`](../workflow.js) 提供模板欄位、初始值、公開白名單與狀態轉換。[`corpus.js`](../corpus.js) 及模板設定提供合成來源。修改規則後以測試保護欄位、流程與索引邊界。
- **輸入／輸出：**使用者表單、合成文字、[品管彙總 JSON](../INTEGRATION.md) → 報告、證據段落與狀態事件 → 公開版預覽與內部 JSON。展示版資料停留在同一瀏覽器；沒有跨人同步或正式交換 API。
- **展示交付：**原始碼、二套合成案例、匯出／匯入樣本及操作方法、六張實拍與可重跑測試。詳見[驗證／驗收矩陣](ACCEPTANCE.md)。

| 建議里程碑（非承諾時程） | 業務／資訊窗口責任 | 實作者交付責任 |
| --- | --- | --- |
| 需求定版 | 確認角色、欄位、公告邊界、樣本與驗收標準 | 欄位字典、流程圖、風險及需求追溯表 |
| 測試環境 | 驗證介接帳號、去識別測試資料、權限與限制 | 建置與部署文件、介面契約、測試報告、資安修正紀錄 |
| 使用者驗證與移交 | 指派參與者、判定測試結果及缺失處置 | 操作／維運手冊、教育訓練、備份還原演練紀錄、版本交付清單 |

展示版不接收實際機關個資或機敏資料；正式範圍以後續核定文件為準。
